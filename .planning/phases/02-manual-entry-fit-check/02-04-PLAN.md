<objective>
Catalog browsing, size pick, fit verdict with breakdown and recommendation, three-preference comparison, and history. Plain unstyled HTML (no CSS work, per user). Completes the Phase 2 vertical slice.

Purpose: the user-visible core value: pick a size, get a trustworthy answer.
Output: catalog and fit views wired into fitApp, i18n for every code the engine emits, a flow test.

Decisions: the Fit section appears only when a profile exists and all three measurements are saved; otherwise a translated hint points to the measurement form. The preference selector (radio group regular/loose/oversize) is saved in state.preference on change (FIT-01) and defaults to regular. Check fit appends a history entry with `at = new Date().toISOString()` created in fitApp.js (the app layer, never core). The comparison table (FIT-06) is always rendered after a check, using recommendAll on the same body. Chart widths are flat and ASSUMED; the chart note says so. Tables are built with createElement/textContent only (innerHTML is forbidden by the privacy guard).
</objective>
