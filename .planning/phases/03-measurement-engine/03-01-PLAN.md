<decisions>
Recorded here because Phase 3 has no CONTEXT.md (user asked for no questions):
- P3-D1: src/core/measure.js, the MEASUREMENTS registry, BUST_BAND_* and the bust row rule in mask.js stay byte-for-byte unchanged (frozen with PASS-CRITERIA.md). Phase 3 measurements live in a new module src/core/scan.js that calls measureView. test/core/measure.test.js ("registry has exactly shoulder and bust, no waist") stays as is: it describes the frozen spike registry.
- P3-D2: Waist is included as an estimate-marked measurement per ROADMAP Phase 3, although GO-NO-GO D-06 was never formally decided. Waist row = narrowest midline torso run in a band from 0.55 to 0.80 of the shoulder-midpoint-to-hip-midpoint distance, per view; circumference = Ramanujan ellipse of half front width and half side depth.
- P3-D3: Torso length (estimate) = front-view distance from shoulder midpoint to hip midpoint in px times that view's cmPerPx. Neck base sits above the shoulder joints and the hip bone above the hip joints by similar amounts, so no prior offset.
- P3-D4: Arm length (estimate) = front view, per side, dist(shoulder, elbow) + dist(elbow, wrist) when all three landmarks have v >= MIN_VISIBILITY; mean of the visible sides; null when neither side is visible.
- P3-D5: Calibration = one table, value = rawCm * scale + offsetCm. Priors: shoulder offset +2.0 cm (DEFINITIONS.md: joint centres read 1 to 3 cm below the acromion), every other entry identity. Each entry carries source "prior"; plan 03-05 replaces priors with tape-fitted values (source "fitted").
- P3-D6: Final values are rounded to 0.1 cm in combineScan, so the Phase 2 form (which re-fills with one decimal) does not turn an unchanged scanned value into "edited".
</decisions>
