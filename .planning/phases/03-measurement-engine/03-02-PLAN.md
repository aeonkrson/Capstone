- P3-D7: Reason codes (stable strings, the UI maps them to text): "no-pose", "no-mask", "not-full-body", "too-close", "too-far", "low-visibility", "wrong-side", "tilted", "arms-against-body", "moving". checkFrame returns the first failure in exactly that order.
- P3-D8: Thresholds live in one exported frozen object QUALITY so they can be tuned in one place after the team runs (plan 03-05): MIN_BODY_FRAC 0.5, MAX_BODY_FRAC 0.97, MAX_LEAN_DEG 6, MAX_SHOULDER_ROLL_DEG 8, FRONT_MIN_SHOULDER_RATIO 0.35, SIDE_MAX_SHOULDER_RATIO 0.25, ARM_GAP_ROW_FRACS [0.35, 0.55], MAX_DEVICE_PITCH_DEG 10, MAX_ANCHOR_DRIFT_FRAC 0.04, MAX_MAD_CM 1.0. All are starting values (ASSUMED), to be confirmed on real captures.
- P3-D9: Side view accepts either side (left or right) facing the camera; "wrong-side" means facing the camera during the side capture, turned sideways during the front capture, or back to the camera during the front capture.
- P3-D10: Camera tilt is checked two ways: image-based (body axis lean and shoulder-line roll, works on every device) and, where the browser exposes deviceorientation, the phone's pitch off vertical. Laptops have no sensor and use the image check only.
</decisions>

<interfaces>
Existing: maskBBox(mask), rowRuns(mask, row) (mask.js); MIN_VISIBILITY 0.5 (measure.js); LM (landmarks.js); median, mad (geometry.js). FrameObservation shape in src/core/types.js (lm in raw unmirrored image px, mask in mask px).

Reading shape consumed by checkStability (created by plan 03-01 readFrame, do not import scan.js here): ok readings with { shoulderCm: number|null, bustExtentCm: number, anchors: { shoulderMid: {x,y}, hipMid: {x,y}, span } }.

New contracts:
- QUALITY (Object.freeze, values per P3-D8).
- checkFrame(obs, view, { devicePitchDeg = null } = {}) -> { ok: true } | { ok: false, code }. Rules in order:
  1. no obs or lm length < 33 -> no-pose; no mask or empty mask -> no-mask.
  2. not-full-body: mask bbox touches any mask edge (top, bottom, left or right), or nose (0) v < MIN_VISIBILITY, or front view with either ankle (27, 28) v < MIN_VISIBILITY, or side view with both ankles below it.
  3. body fraction = bbox height / mask height: > MAX_BODY_FRAC -> too-close, < MIN_BODY_FRAC -> too-far.
  4. shoulders 11/12 or hips 23/24 v < MIN_VISIBILITY -> low-visibility.
  5. ratio = |ls.x - rs.x| / span (span = hipMid.y - shoulderMid.y, span <= 0 -> low-visibility). Front: ratio < FRONT_MIN_SHOULDER_RATIO, or ls.x < rs.x (back to camera in the raw unmirrored image) -> wrong-side. Side: ratio > SIDE_MAX_SHOULDER_RATIO -> wrong-side.
  6. tilted: devicePitchDeg is a number and > MAX_DEVICE_PITCH_DEG; or the angle from vertical of the line from the visible-ankle midpoint to shoulderMid > MAX_LEAN_DEG; or front view shoulder-line angle from horizontal > MAX_SHOULDER_ROLL_DEG.
  7. Front only, arms-against-body: at each frac in ARM_GAP_ROW_FRACS, the image row shoulderMid.y + frac * span (mapped to mask rows) must have at least 3 runs (left arm, torso, right arm), else arms-against-body.
- checkStability(readings) -> { ok: true } | { ok: false, code: "moving" }. moving when, over the readings, the range (max - min) of shoulderMid.x, shoulderMid.y, hipMid.x or hipMid.y exceeds MAX_ANCHOR_DRIFT_FRAC * median(span), or mad of the non-null shoulderCm values or of bustExtentCm exceeds MAX_MAD_CM. Fewer than 2 readings -> ok.
- cameraPitchDeg(betaDeg, gammaDeg) -> degrees the screen plane is off vertical = asin(min(1, |cos(beta) * cos(gamma)|)) in degrees; null if either input is not a finite number. Upright portrait (beta 90) and upright landscape (gamma +-90) give 0; flat on a table gives 90.
- src/platform/tilt.js: createTiltSensor({ target = globalThis, OrientationEvent = globalThis.DeviceOrientationEvent } = {}) -> { start(): Promise<boolean>, pitchDeg(): number | null, stop(): void }. start() calls OrientationEvent.requestPermission() when it is a function (iOS; must be called from a click handler) and returns false unless it resolves "granted"; otherwise adds a "deviceorientation" listener on target and returns true. The listener keeps the latest event.beta and event.gamma. pitchDeg() returns cameraPitchDeg of the latest values or null when no reading has arrived. stop() removes the listener and clears the reading. Any thrown error resolves false (no sensor -> image check only, per P3-D10).
</interfaces>
