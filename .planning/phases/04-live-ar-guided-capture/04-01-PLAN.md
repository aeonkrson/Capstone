Phase 4 decisions (recorded by the planner; no CONTEXT.md exists, user asked for no questions):
- P4-D1: The auto-lock state machine lives in src/core as a pure reducer. Time comes in on each event (`t`, ms, same clock as the frame loop). core.purity.test forbids Date.now, performance, window, document, navigator.
- P4-D2: Per-frame correctness reuses `checkFrame` from src/core/quality.js unchanged (caller passes its result in as `gate`). Hint codes are the Phase 3 reason codes; UI text reuses the existing `scan.reason.<code>` strings.
- P4-D3: Lock = HOLD_MS (1500 ms) of consecutive ok frames whose shoulder/hip midpoints stay within MAX_HOLD_DRIFT_FRAC (0.05) of the torso span from the first ok frame of the hold. Then the machine asks for a capture; the app runs the existing Phase 3 burst (`runBurst`), which applies checkStability. Values are starting values, tuned in Phase 5.
- P4-D4: After the front locks, a TURN phase lasts TURN_MS (2500 ms) before side guiding starts, so the front pose cannot instantly be judged for the side.
- P4-D5: Cues are names only here: "hold", "captured", "turn". Hold cue is rate-limited by HOLD_CUE_GAP_MS (2000 ms).

<interfaces>
From src/core/quality.js:
- `checkFrame(obs, view, { devicePitchDeg })` returns `{ ok: true }` or `{ ok: false, code }` where code is one of no-pose, no-mask, not-full-body, too-close, too-far, low-visibility, wrong-side, tilted, arms-against-body.
From src/core/landmarks.js: `LM` object with LEFT_SHOULDER, RIGHT_SHOULDER, LEFT_HIP, RIGHT_HIP indices. Landmarks are `{ x, y, z, v }` in image px.
From src/app/burst.js (consumer side, not imported here): runBurst resolves `{ ok: true, ... }` or `{ ok: false, code, reason? }` with code "aborted", "burst-too-few" or "moving".

Contract this plan creates (later plans code against it exactly):
- `export const AUTO_LOCK = Object.freeze({ HOLD_MS: 1500, TURN_MS: 2500, MAX_HOLD_DRIFT_FRAC: 0.05, HOLD_CUE_GAP_MS: 2000 })` each with a "starting value (ASSUMED)" comment like QUALITY.
- `export function initialLock()` returns `{ phase: "guide", view: "front", since: null, ref: null, hint: null, lastHoldCueT: null }`.
- `export function bodyAnchors(lm)` returns `{ shoulderMid: {x,y}, hipMid: {x,y}, span }` (span = hipMid.y - shoulderMid.y) or null when lm is missing, shorter than 33, or span <= 0.
- `export function stepLock(state, event)` returns `{ state, cues: string[], action: null | { type: "capture", view: "front" | "side" } }`. Never mutates the input state. Events:
  - `{ type: "frame", t, gate: { ok, code? }, anchors: object | null }`
  - `{ type: "capture-done", t, view, ok: boolean, reason: string | null }`
  - `{ type: "restart" }`
- Phases: "guide" -> "hold" -> "capturing" -> ("turn" -> "guide" side ->) ... -> "done".
- `export function lockMessageKey(state)` returns the i18n key to show: guide with hint -> "scan.reason." + hint; guide without hint -> "guide.front" or "guide.side"; hold -> "guide.hold"; capturing -> "guide.capturing"; turn -> "guide.turn"; done -> "guide.done".
</interfaces>

  <behavior>
    Build test frames with a helper `okFrame(t, dx = 0)` returning `{ type: "frame", t, gate: { ok: true }, anchors }` with anchors shoulderMid (240 + dx, 140), hipMid (240 + dx, 390), span 250, and `badFrame(t, code)` with anchors null.
    - initialLock() is guide/front with null hint; lockMessageKey gives "guide.front".
    - guide + bad frame "too-far": stays guide, hint "too-far", no cues, no action; lockMessageKey "scan.reason.too-far".
    - guide + ok frame at t=0: phase hold, since 0, cues ["hold"], ref = those anchors, hint null.
    - ok frames at t=0,100,...,1400: still hold, no action. ok frame at t=1500: phase capturing, action { type: "capture", view: "front" }, no extra cue.
    - hold + bad frame "arms-against-body": back to guide with hint "arms-against-body", no action.
    - hold + ok frame with dx = 20 (> 0.05 * 250 = 12.5 px): back to guide, hint "moving". dx = 10 stays hold.
    - hold cue rate limit: enter hold at t=0 (cue), break with a bad frame at t=300, re-enter at t=400 -> no cue; re-enter at t=2100 -> cue "hold".
    - capturing ignores frames (state unchanged, no cues, no action).
    - capture-done front ok at t=5000: phase turn, view side, since 5000, cues ["captured", "turn"]. Frames before t=7500 keep turn even when ok; ok frame at t=7500 -> guide side (that frame does not start a hold; the next ok frame does).
    - Full side path: guide side -> hold -> capture side -> capture-done side ok -> phase done, cues ["captured"]; frames in done do nothing.
    - capture-done ok:false reason "moving" during capturing front -> guide front, hint "moving", no cue. reason "aborted" or null -> hint null.
    - capture-done whose view differs from the capturing view, or arriving when not capturing, is ignored.
    - restart from any phase returns initialLock().
    - stepLock does not mutate its input (deep-freeze the input state in one test).
    - bodyAnchors on a 33-landmark array computes midpoints and span; returns null for null, short arrays, or span <= 0.
