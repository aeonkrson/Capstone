Decisions:
- P4-D6: Review order and keys are SCAN_KEYS from src/core/scan.js: shoulderCm, chestCm, waistCm, torsoCm, armCm. Estimate flag comes from ESTIMATE_KEYS (waist, torso, arm), derived not stored (same as P3-D12).
- P4-D7: A row is "scanned" when its value equals the scanned value after rounding both to 0.1 cm; otherwise "edited". A key with no scanned value that the user types is "edited".
- P4-D8: chest, shoulder and torso are required to save (fitApp's bodyOf needs all three); waist and arm are optional (empty means not saved, old value kept).
- P4-D9: applyReview is the only new state function; no STATE_VERSION bump, sources stay within the existing whitelist ("typed", "edited", "scanned").

<interfaces>
From src/core/bodyMeasurements.js:
- `BODY_FIELDS` keys chest, shoulder, torso, waist, arm with { min, max }.
- `validateBodyMeasurement(key, input)` -> `{ ok: true, cm }` or `{ ok: false, code: "empty" | "not-a-number" | "too-low" | "too-high" }`; accepts one comma as decimal point.
From src/core/scan.js: `SCAN_KEYS`, `ESTIMATE_KEYS`.
From src/core/profileState.js: `MEASUREMENT_KEYS`, internal `cloneState`, `inRange(stateKey, value)`, `FIELD_MAP` (state key -> BODY_FIELDS key), `applyScan` returns `{ state, applied, rejected }`.

Contract this plan creates:
- src/core/review.js:
  - `export const REVIEW_KEYS = SCAN_KEYS` (re-export the same order).
  - `export const REQUIRED_REVIEW_KEYS = ["shoulderCm", "chestCm", "torsoCm"]`.
  - `export function reviewRows(scanned, values)` -> array in REVIEW_KEYS order of `{ key, scannedCm: number | null, valueCm: number | null, source: "scanned" | "edited" | null, estimate: boolean }`. source null when valueCm is null.
  - `export function parseReviewInputs(texts)` where texts maps state key -> raw string. Returns `{ ok: true, values }` (values maps every REVIEW_KEY to number or null) or `{ ok: false, values, errors }` where errors maps state key -> code. Empty optional field -> null, no error. Empty required field -> code "empty".
- src/core/profileState.js: `export function applyReview(state, scanned, values)` -> `{ state, applied, rejected }`. For each MEASUREMENT_KEY: null/undefined value -> skip (not applied, not rejected); out of range -> rejected, state unchanged for that key; else stored rounded to 0.1 with source "scanned" if equal to rounded scanned value, else "edited".
</interfaces>
