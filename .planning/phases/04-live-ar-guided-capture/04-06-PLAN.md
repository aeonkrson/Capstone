Contract this plan creates:
- `createReviewView({ doc, t, formatNumber, onSave })` returns `{ show({ scanned, hasProfile }), hide(), refresh(), isShown() }`.
  - show fills each input with formatNumber(value) or "" when null, clears errors and status, toggles the name row by hasProfile, renders markers, unhides the section and scrolls it into view.
  - Markers: on every input event, parse current texts with parseReviewInputs, then reviewRows(scanned, result.values); marker text = t(estimate ? "review.marker-estimate" : "review.marker", { source: t("review.source." + (source ?? "missing")) }).
  - Submit: preventDefault, parseReviewInputs; show per-field errors via body.error.{code} with BODY_FIELDS min/max (focus first bad input) or call `onSave({ name, scanned, values })` and handle its return: `{ ok: false, code: "name-empty" | "name-too-long" }` shows profile.name.error.{empty|too-long} in review-name-error; ok shows review.saved.
  - refresh() re-renders markers and status text in the current language (called on language change).
- fitApp handle gains:
  - `applyReview({ name, scanned, values })` -> `{ ok: true, applied, rejected }` or `{ ok: false, code: "name-" + code }` (P4-D21). Uses one update() call. Resets lastCheck.
  - `hasProfile()` -> boolean.
  - `goToFitCheck()` (P4-D22).
  - `showManualEntry(messageKey)` (P4-D19).
  Existing `applyScan`, `render`, `getState` stay as they are.
</interfaces>
