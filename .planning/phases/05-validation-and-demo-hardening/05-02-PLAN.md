<feature>
  <name>Phase 5 study evaluator</name>
  <files>validation/study.mjs, test/validation.study.test.js, validation/study-readings.csv, validation/STUDY-RESULTS.md</files>
  <behavior>
    Parsing (HEADER = "subject,device,browser,measurement,repeat,tape1_cm,tape2_cm,scan_cm,notes"):
    - header only -> []; wrong header -> throws with the expected header in the message
    - subject must match /^S[1-9]$/; device in iphone|android|laptop; browser in safari|chrome|firefox|edge|other; measurement in shoulder|chest|waist|torso|arm; repeat /^[1-9]$/; tape1_cm, tape2_cm, scan_cm /^\d+(\.\d+)?$/; notes has no comma or newline, at most 80 chars, and does not contain an image or video file name (/\.(png|jpe?g|heic|webp|gif|mp4|mov|webm)\b/i)
    - a bad field throws "Row N: invalid <field>" with N the file line number
    Analysis (analyseStudy(rows)):
    - tape value per subject = mean of all tape1 and tape2; scan value = median of the repeats; error = scan - tape
    - cells for each measurement x device in [iphone, android, laptop, phone] where phone = iphone + android rows (a subject scanned on both phones counts once per phone, scan median over all its phone repeats)
    - each cell: n (subjects), subjects (sorted IDs), mae, maxAbs, meanSigned, maxRepeatRange (largest scan range of any subject); all null and n 0 when no rows
    - targets per class phone and laptop: shoulder MET when n >= MIN_SUBJECTS and mae <= TARGETS.shoulderMaeCm (2.5); chest MET when n >= 2 and mae <= TARGETS.chestMaeCm (3.5); sizeAgreement MET when n >= 2 and every chest subject agrees, where agree means recommendSize(scan).label === recommendSize(tape).label, or recommendSize(scan).borderline and its neighbour === tape label; any target with n < 2 is "INSUFFICIENT DATA", else "NOT MET"
    - overall: "INSUFFICIENT DATA" if any of the six class targets is INSUFFICIENT DATA; "GO" if all six MET; "CONDITIONAL" if all three MET for one class; else "NO-GO"
    - waist, torso, arm are reported in the table as estimates with no target
    Fixtures (all made-up test data inside the test file only, never in validation/):
    - two subjects on iphone and laptop with small errors -> GO
    - laptop shoulder mae 3.0 -> phone MET, laptop NOT MET -> CONDITIONAL
    - one subject only -> INSUFFICIENT DATA
    - chest where scan size differs and is not borderline toward tape -> sizeAgreement NOT MET
    Rendering (renderMarkdown(result)):
    - starts with "# Phase 5 study results", a "Generated by node validation/study.mjs --write. Do not edit by hand." line, the labelling line "Everyday clothes, team members only, N subjects (IDs)", a table with columns Measurement | Device | n | Subjects | Mean abs error (cm) | Max error (cm) | Mean signed (cm) | Max repeat range (cm), "no data" for null cells, a Targets table, and "Overall outcome: X"
    CLI: no flag prints the markdown; --check prints "OK: N rows"; --write writes validation/STUDY-RESULTS.md next to the script; optional path argument for the CSV
  </behavior>
